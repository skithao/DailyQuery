# DailyQuery 平台规范 (Spec)

## Why
用户需要一个能够智能获取、筛选并深入分析资讯的跨平台工具。当前的资讯平台缺乏深度互动的多智能体分析能力，也无法根据用户的具体日程和兴趣进行高度定制。DailyQuery 旨在通过结合强大的 AI 爬虫、多智能体架构和自定义 Skill 生态，打造一个面向 Web 端和 APP 端的多智能体资讯推送与分析平台，帮助用户更高效、深度地消费和探讨每日资讯。

## What Changes
- **创建项目基础架构**：核心业务逻辑与爬虫/数据处理采用 Rust 实现，Web 端与跨平台编译采用合适的框架（如 React/Next.js 结合 Tauri 或 Capacitor，不使用 Android Studio）。
- **实现信息流页 (Feed)**：构建类似知乎的资讯瀑布流，支持点击查看原文，并在原文上实时划词唤起智能体讨论或进入多智能体研讨室。
- **实现对话页 (Chat)**：预设初始化引导、日程设计、资讯深入讲解等对话流，用户可通过对话框提出需求。
- **实现设置页 (Settings)**：包含简单的登录等鉴权功能，支持修改智能体的各类配置信息。
- **集成 AI 爬虫与 WebSearch**：参考 Crawl4AI 和 FireCrawl，实现对最新新闻热点和各类 RSS 订阅的爬取、分类、存储、检索，并与用户的兴趣进行匹配。
- **搭建多智能体架构**：参考 HermesAgent 和 NanoClaw 的智能体架构设计，实现多智能体协作与研讨。
- **构建 Skill 市场与生态**：集成 awesome-open-claw-skills、CoCoLoop Skill Hub、agent-skills 等开源 skill 库作为 skill 市场；允许用户使用平台自制 skill，并参考扣子的虾评社区实现 skill 安全评估功能。
- **引入多维记忆系统**：参考 Mem0、Letta、Zep 等方案实现长期与短期记忆，并将存储分为 `.md` 文件与 SQL 数据库两类，用于存储对话上下文、兴趣匹配等。
- **构建知识库系统**：参考 MaxKB 实现知识库的管理与调用。
- **规范工程流程**：开发过程中详细记录所有 todo 及其优先级；随时检查项目结构，发现有问题随时修复 bug 或重构；写好详细的单元测试；要求实时更新到 `https://github.com/skithao/DailyQuery` 仓库，每次更新前进行严格的 Code Review。

## Impact
- Affected specs: 这是一个全新的平台级项目，涉及前后端分离架构、爬虫服务、多智能体编排、知识库与记忆系统、以及跨平台 APP 编译。
- Affected code: `DailyQuery` 环境及仓库下的所有代码（包括前端 Web、跨平台 App 包装、Rust 核心服务、数据库与记忆系统模块等）。

## ADDED Requirements
### Requirement: 资讯信息流与划词多智能体研讨
系统需提供瀑布流资讯展示，并在详情页支持选中内容进行讨论。
#### Scenario: 划词研讨与讨论
- **WHEN** 用户在资讯详情页选中一段文本
- **THEN** 弹出快捷交互面板，允许用户选择“与智能体讨论”或“进入多智能体研讨界面”，系统自动携带选中的上下文并初始化相应的智能体对话。

### Requirement: 多智能体与 Skill 生态系统
系统需支持多个智能体协同工作，并允许用户接入、创建和评估 Skill。
#### Scenario: 用户提交并使用自制 Skill
- **WHEN** 用户在 Skill 市场提交一个自制 Skill
- **THEN** 系统先通过内置的安全评估模块（参考虾评社区）进行自动化审查，通过评估后才允许该 Skill 上架并在多智能体对话中被调用。

### Requirement: 数据采集与基于记忆的兴趣匹配
系统需利用 AI 爬虫与搜索获取全网资讯及 RSS，并与用户的记忆系统（SQL 与 `.md` 存储的兴趣标签）进行匹配推送。
#### Scenario: 资讯个性化优先展示
- **WHEN** 爬虫入库了一批新的热点新闻，且用户进入信息流页
- **THEN** 系统根据用户的长期记忆和当前设置，对资讯进行分类与过滤，将高匹配度的新闻展示在瀑布流顶部。
